# 二人世界 · 游戏重做方案（交给 Codex 执行）

> 仓库：`lanco-ai/duo-games`，基于提交 `bb2c502`。
> 本文是**执行规格**：每款游戏写明现状问题（附代码位置）、新玩法、关卡、双人互动、同步方式、验收标准。按「阶段」顺序做，每个阶段单独提交、单独跑测试。

---

## 0. 给 Codex 的全局约束（每个阶段都适用）

1. **沿用现有架构**：服务端引擎继承 `server/games/base.ts` 的 `BaseEngine`，实现 `view(seat)` / `act()` / `tick()` / `shift()`；在 `server/games/index.ts` 注册；前端组件放 `web/src/games/`；元数据改 `shared/catalog.ts`；设置项改 `web/src/games/Setup.tsx`。
2. **按座位裁剪视图**：凡是「对方不该看到」的信息（答案、藏身处、对方手牌、地图），只能出现在对应座位的 `view(seat)` 里。每个新引擎都要有一条单测断言这一点。
3. **暂停/重连**：所有带时间的字段（deadline、cooldown、锅里的计时……）都要在 `shift(ms)` 里平移，否则断线暂停后会直接超时。
4. **随机性只用 `shared/rng.ts`**（`mulberry32` / `shuffled`），保证同一个种子能复现。
5. **同设备双人**（`p.local`）：厨房、躲猫猫、跳一跳、默契挑战已支持；新玩法要继续支持，或者在 catalog 里明确标注「需两台设备」。
6. **内容与逻辑分离**：题目、关卡、地图、任务全部放在 `shared/content/` 或 `shared/games/<id>/levels.ts`，不要写死在引擎里。
7. **每阶段完成后必须通过**：`npm run typecheck`、`npm test`、`npm run build`、`npm run check:size`（首屏 JS gzip 不超过现在的 37 KiB 太多；新游戏用懒加载拆包）。新增玩法要补 `tests/unit` 引擎测试和至少一条 `tests/e2e` 双浏览器开局→结算用例。
8. 不改通信协议的大版本；如必须加字段，向后兼容。不碰部署脚本和 `deploy/`。

## 1. 现状诊断（为什么感觉「做得不好」）

| 游戏 | 主要问题 | 代码位置 |
|---|---|---|
| 情侣求生欲 | 答案一眼就能看出（好回答总是最长、最温柔的那个），没有思考空间；「找线索」与题目无关：每个场景都是同样 4 个物品（口红/手机/礼物盒/纸条），`hint` 文案写的「日历」「伞」在画面上根本不存在；只有一个人答题，另一个人无事可做 | `shared/games/couple-content.ts` `survivalLevels`；`server/games/couple-puzzles.ts` `Survival`；`CoupleGames.tsx` `Survival` |
| 情侣找茬 | 5 个场景共用**同一组 10 个物品、同一坐标**，玩两局就背下来了；差异只是翻转/放大/透明/平移 3px，有的几乎看不出；两人看的是同一张图，没有分工 | `differenceObjects`；`SpotDifference` |
| 双人厨房 | 只有汉堡、沙拉两道菜；每走一格都要点按钮并等服务器往返，操作很卡；只有一个装盘台，两人抢着用；没有关卡、没有星级，3 分钟一成不变 | `server/games/couple-action.ts` `CoopKitchen` |
| 情侣飞行棋 | 纯掷骰子，玩家零决策；格子事件按 `pos % 4` 循环，毫无变化；任务池每档只有 2–3 条，很快重复；起飞规则奇怪（第一次投任何点数都只到 0 格） | `CoupleLudo`；`ludoTasks` |
| 双人躲猫猫 | 12 个格子 + 3 种家具 emoji，没有空间感；回合模式就是「三次猜中 1/12」，纯运气；实时模式的规则（照亮房间、走 ±3 格、拾钥匙）界面上很难理解 | `HideSeek` |
| 双人跳一跳 | 界面直接写「目标力度约 1.2 秒」，变成了看秒表按键，没有跳一跳的距离感；**同步模式有漏洞**：两人松手相差 <150ms 就判定成功，与目标无关，两人一起随便按就能无限得分 | `CoupleJump.resolveJump` 中 `landed = perfect \|\| …` |
| 心跳节拍 | 谱面完全机械：每拍一个音符、每两拍换一次轨、每小节第一拍是合拍音符，三首歌只有速度不同 | `shared/games/heartbeat/chart.ts` |
| 其他 9 款（聊天卡、你画我猜、心有灵犀、你懂我吗、五子棋、一线牵、你是我的眼、颠颠爱心、拼出我们） | 整体完成度不错，只需小幅打磨（见第 4 节） | — |

**共性问题**：新加的 6 款都是「一个人操作、另一个人旁观」或「两人做完全一样的事」，缺少**信息不对称**和**分工**——而这恰恰是双人游戏最好玩的地方（参考《双人成行》《胡闹厨房》《Keep Talking》）。

**设计原则（全部新方案遵守）**
- **非对称**：两人看到的信息或拥有的能力不同，必须交流才能过关。
- **双人都有事做**：任何时刻两个人都有操作，没有「等 TA 做完」的空窗。
- **有关卡、有成长**：每款至少 3 个难度递进的关卡，有 1–3 星评价，解锁下一关。
- **结算有回忆**：每局留下一句可以截图的话或一张图（存进现有画廊/战绩）。

## 3. 各游戏新方案

### P1 · 双人跳一跳 `couple-jump`（保留名）

**先修漏洞**：删除 `landed = perfect || …` 里的 `perfect ||`，「心有灵犀」只作为**加分**，不能代替落地判定。补一条单测：两人同时按 0ms 松开，必须掉下去。

**新玩法：看得见的距离**
- 横版 2.5D 画面（SVG 即可）：当前平台、下一块平台、两块之间的**真实距离**（像素）。蓄力时间 → 跳跃距离线性换算（如 1ms = 0.25px），**不再显示秒数**，靠眼睛估。
- 平台有宽度，落在平台上算成功，落在中心圆点 ±8% 范围算「正中」。
- 两种模式：
  - **接力**：两人轮流跳，同一个角色（红线连着的两只小动物，跳的那只拉着另一只）。
  - **同步**：两人各控制一只，必须**同一时间起跳**（松手相差 ≤300ms），各自的蓄力决定各自的落点；两只都落在平台上才算过，两只都正中 + 同时松手 = 「心有灵犀」×2 分。两人可以分别落在**两块不同的平台**上（下一组平台成对出现，一高一低），所以蓄力目标不一样。
- **关卡**：不是无尽乱跳，而是「旅程」：
  1. 草地（平台大、距离近，10 跳）
  2. 雪山（平台变小，出现会融化的冰块：站上去 2 秒后消失，必须马上跳）
  3. 云端（出现左右移动的平台）
  4. 星河（平台小 + 移动 + 偶尔有一块「爱心平台」，两人同时正中可以 +1 条命）
  每关 3 条命，掉下去扣一条命并回到当前平台；通关按命数给 1–3 星。最后提供「无尽模式」。
- **同步**：服务器权威。按下发 `press{n}`，松开发 `release{n, heldMs}`；服务器用自己记录的时间戳计算 heldMs（客户端值只用于本地预演动画），防作弊。客户端松手后立即播放本地预测的抛物线，服务器结果到达后若不一致，在落地前 100ms 内修正。
- **验收**：给定种子与蓄力序列，结果可复现；断线暂停后移动平台位置正确（`shift`）；同设备双人可玩。

### P2 · 双人厨房 `coop-kitchen`（保留名）

**操作改造（最重要）**
- **移动在本地预测**：摇杆/方向键在客户端连续移动（每秒 4 格，平滑插值），以 15Hz 发 `cur pos{x,y}`（可丢）；服务器只校验「不穿墙、不瞬移超过 2 格」。**交互**（拿、放、切、出菜）才走 `act`，并由服务器判定。
- 交互改为「面朝的工作台 + 一个大按钮」，不再在屏幕上列出所有工作台按钮。切菜改为**按住**大按钮（2 秒进度条），而不是连点三次。

**关卡（5 关 + 无尽）**，每关数据放 `shared/games/coop-kitchen/levels.ts`：

| 关 | 名称 | 地图机制 | 菜品 | 时长 | 星级线（分） |
|---|---|---|---|---|---|
| 1 | 第一次约会便当 | 开放厨房 | 沙拉、三明治 | 120s | 200 / 400 / 600 |
| 2 | 中间的吧台 | 地图中间一道吧台隔开两人，**只能通过吧台传递食材** | 汉堡、沙拉 | 150s | 300 / 600 / 900 |
| 3 | 火锅夜 | 新增锅（煮 8s、15s 煮烂），菜品要「切+煮」 | 火锅、汉堡 | 180s | 400 / 800 / 1100 |
| 4 | 移动餐车 | 每 30s 两人的工作区**左右互换**（食材架换边） | 全部 | 180s | 500 / 900 / 1300 |
| 5 | 纪念日蛋糕 | 一份大订单需要 6 个步骤，两人必须同时在两个台子上操作（同时按住才会「打发奶油」） | 蛋糕 + 普通订单 | 200s | 600 / 1000 / 1500 |

- 菜谱：三明治（面包+切番茄）、汉堡（面包+煎肉+切生菜）、沙拉（切番茄+切生菜）、火锅（切菜+煮肉）、蛋糕（专用流程）。食材做成数据表，新增菜只改数据。
- **装盘台 2 个**，盘子可拿起移动；脏盘子回到洗碗池（关 3 起），需要洗（按住 2 秒）。
- 订单：屏幕上方最多 4 张票，剩余时间条；**连续准时出菜有小费连击**（×1.0→×1.5）。超时扣分但不结束。
- 结算：星级、各自贡献（切菜次数、出菜数、传递次数），一句评语（「最佳传菜搭档」等）。
- **验收**：两人同时对同一工作台交互只有一人成功；关 2 无法绕过吧台；`shift` 后锅的时间正确；无尽模式订单速度递增且上限可控；同设备双人（键盘 WASD + 方向键）可玩。

### P3 · 情侣求生欲 → 「求生欲·双人版」（id 仍为 `survival`）

**核心改动：从「挑温柔的选项」变成「猜对方心里想听什么」。**

- 每题有一个**提问者**和一个**回答者**，每题轮换。
- 流程（每题约 40 秒）：
  1. 场景 + 一句话（如「你觉得我今天哪里不一样？」）。
  2. **提问者**在 4 个选项里**秘密**选出「我最想听到的」（可选「都不对，我自己写」，限 20 字）。
  3. **回答者**看到同样 4 个选项，选一个回答，或者自己打字回答（限 30 字）。
  4. 同时揭晓：选中 = 「求生成功」；没选中 → 提问者给打分（😍 加分 / 😐 不扣 / 😤 扣一颗心），并显示「其实我想听的是……」。
- 选项不再有标准答案，4 个都要像样（例：「换了新发型」「今天特别有精神」「穿了我送的那件」「没变，一直这么好看」），这样才需要真的了解对方。
- **线索玩法保留但做对**：每个场景真正画出 3–4 个可点击物品，物品与题目相关（提问者在第 1 步可以「藏」一个线索物品高亮给回答者，花费 1 次提示）。删掉与画面不符的 `hint` 文案。
- **关卡 = 章节**，每章 5 题，按恋爱阶段排列：
  1. 暧昧期（轻松）
  2. 热恋期（生活细节）
  3. 磨合期（吵架与和好，例如「我生气的时候你最该做什么」）
  4. 见家长（带点紧张感）
  5. 纪念日（走心）
  每章 3 颗心，心全掉了可以「撒娇复活」一次（回答者录一句话/打一段字给提问者确认）。
- 题库：至少 75 题（5 章 × 15，每局抽 5），放 `shared/content/survival.ts`，延续现有「原创、不引用第三方」要求。
- **视图裁剪**：提问者的选择在揭晓前不能出现在回答者视图里（单测断言）。
- 结算：每章的「求生指数」，以及「TA 最想听的 3 句话」，可保存为卡片到画廊。

### P4 · 情侣找茬 → 「各看一半」（id 仍为 `spot-difference`）

**核心改动：两人看到不同的图，必须口头描述才能找到不同。**

- **玩家 A 只看原图，玩家 B 只看修改图**（服务器只把对应图的差异数据下发给对应座位；`view(seat)` 裁剪）。
- 两人通过描述（语音或房间内置聊天、快捷短语：「左上角」「桌子上」「有几个」）找出不同；任何一人点击位置即可提交，点对后两边都显示圆圈。
- 点错扣 3 秒，并让另一方屏幕在该位置闪一下（帮助对齐描述）。
- 可选「同屏简单模式」：两图都给双方看（旧玩法），作为第 1 关新手教学。
- **场景数据重做**：每个场景独立的 SVG 构图与物品列表（不能再共用 `differenceObjects`），每个场景 ≥ 15 个可变物品，每局随机抽 5–7 个差异。差异类型：颜色变、物品消失、数量变（2 朵花→3 朵）、方向变、大小变、图案变；每种差异要有**最小可见度要求**（如缩放 ≥1.4 倍、颜色明显不同、平移 ≥ 物体宽度一半）。
- **关卡**：

| 关 | 场景 | 差异数 | 时间 | 模式 |
|---|---|---|---|---|
| 1 | 咖啡厅 | 5 | 90s | 同屏（教学） |
| 2 | 电影院 | 5 | 90s | 各看一半 |
| 3 | 游乐场 | 6 | 100s | 各看一半 |
| 4 | 卧室 | 7 | 110s | 各看一半 |
| 5 | 海边 | 7 | 110s | 各看一半，且画面中有会动的元素（海浪、海鸥），干扰判断 |

  星级：剩余时间 ≥50% 三星、≥25% 两星、完成一星。
- 结算：附带两张图并排的「答案揭晓」图，可保存。

### P5 · 情侣飞行棋 → 「心动棋」（id 仍为 `couple-ludo`）

**核心改动：加入决策和合作，任务不再循环重复。**

- 棋盘：一条 36 格的环形路线（不是十字），按「相遇 → 约会 → 旅行 → 同居 → 承诺」5 个区域着色，每个区域有不同的事件池。
- **每回合投 2 颗骰子，玩家选其中 1 颗走**（另一颗作废）；或者把两颗点数都给对方（「让一步」），对方下回合多走——这就有了决策。
- 格子类型（在关卡数据中逐格定义，不再 `pos % 4`）：
  - 💬 真心话：从当前区域题库抽题，**对方给回答打分**（1–3 颗心），心数 = 前进步数。
  - 🎯 小挑战：两人**一起**完成的现实小任务（拥抱 10 秒、一起说出同一个词——调用心有灵犀的一轮），完成后两人都前进。
  - 🎁 回忆格：写一句共同回忆，存进「问答本」。
  - 🌀 岔路：选择走近路（需要掷出 ≥8）或远路。
  - ⛓️ 红线格：两人棋子距离 >10 格时，落后者被红线拉近 3 格（防止一边倒）。
- **胜利条件改为合作**：两人都到终点「承诺」区即通关；回合数越少星越多。另提供「较量模式」（先到者胜）作为设置选项。
- 任务池：每个区域 ≥ 20 条真心话 + 10 条挑战，分「纯爱 / 甜蜜 / 搞笑」三档强度（沿用现有 `mode` 设置），放 `shared/content/ludo.ts`；同一局内不重复。
- 同步：回合制、服务器权威，延迟不敏感；骰子用种子 RNG，服务器掷。
- 结算：路线图 + 本局写下的回忆卡片列表，可保存。

### P6 · 双人躲猫猫 → 「房间里的秘密」（id 仍为 `hide-seek`）

**核心改动：有空间感的小房子 + 双方都有能力。**

- 地图：俯视的小公寓，4 个房间（客厅、卧室、厨房、阳台），每个房间 5–6 个**有名字的藏身点**（衣柜、窗帘后、浴缸、冰箱旁、沙发下……），共约 22 个，地图数据放 `shared/games/hide-seek/maps.ts`，提供 3 张地图（公寓、木屋、游乐园鬼屋）作为 3 个关卡。
- 每局 3 轮，每轮交换身份，总分高者胜。
- **躲藏者**（30 秒）：选一个藏身点，并布置 **2 个干扰**（如「把门虚掩」「留下一只拖鞋」——在地图上显示为可疑标记）。
- **寻找者**（60 秒、6 次搜查）：点击藏身点搜查，每次搜查有声音反馈：
  - 在同一房间 → 「好像听到呼吸声」
  - 相邻房间 → 「隔壁有动静」
  - 更远 → 「很安静」
  - 搜到干扰 → 「是个陷阱！」并浪费额外 5 秒
- **躲藏者在寻找阶段也有操作**：最多 2 次「换位」（只能换到同房间相邻的点，换位时会发出一次「吱呀」声提示寻找者房间）和 1 次「装死」（下一次搜查无论结果都返回「很安静」）。这样双方一直在博弈。
- 计分：寻找者用的搜查次数越少得分越高；没被找到，躲藏者得满分。
- **视图裁剪**：寻找者视图绝不包含 `hiding` 和真实干扰位置（只有「可疑标记」位置）；单测断言。
- 同设备模式：保留现有「交给对方 / 遮挡屏幕」流程。
- 删除当前实时模式（照亮/钥匙），规则复杂且难以理解。

### P7 · 心跳节拍 + 其他打磨

**心跳节拍（重写 `shared/games/heartbeat/chart.ts`）**

- 每首歌 3 个难度（简单/普通/困难），由同一节奏型的密度控制。
- 验收：同一首歌同一难度谱面固定；困难谱面的最小音符间隔 ≥ 120ms；单测检查两人音符数量差 ≤10%。
