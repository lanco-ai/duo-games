# M0 交付说明

日期：2026-10-23。范围：平台骨架 + 深夜聊天卡。实现依据为 `docs/DESIGN.md`、`docs/GAMES.md`；本次按用户要求直接实施，没有启动工作流或创建工作流检查点。

## 已交付

- 在 `/root/duo-games` 初始化独立 Git 仓库，保留原始设计文档。未执行 commit 或 push。用户随后明确授权部署，已在 [https://lancoai.site/duo/](https://lancoai.site/duo/) 上线。
- Preact + Vite 前端；Node 22 原生 HTTP、`ws`、内置 SQLite 服务端。服务端生产依赖只有 `ws`。
- 完整首页、头像/昵称/玩家色、邀请加入页、大厅、游戏介绍、双方准备、同步倒计时、游戏界面、掉线浮层、结算和双方确认再来一局。
- 十款游戏均有介绍与分类；目前只有深夜聊天卡可开始，其余明确展示“敬请期待”。
- 六位房间码、两个固定座位、128 bit 随机凭证（服务器仅保存 SHA-256 摘要）、新页面接管旧连接、一次性换设备链接、房间解散和过期清理。
- 服务器权威状态机、房间状态版本、每座位最近 200 个动作 ID 去重、限流、心跳、时钟同步、双人延迟、重连退避和 60 秒掉线暂停。
- 聊天与表情、复制链接的两级降级、声音开关、支持设备上的 Wake Lock、简体中文界面、减少动态效果偏好和安全区适配。
- 深夜聊天卡 4 组 × 40 张：轮流抽卡、`flipAt` 同步翻牌、同时下一张只推进一次、跳过、独立收藏、回答与问答本、已聊卡片去重和结算图片。
- 回答草稿固定所属卡片；对方换卡或最后一张结束后，仍能保存到原问题。未来卡片 ID 不可提交回答。
- SQLite 保存资料、凭证摘要、收藏、已聊卡片、回答、结果。问答本通过鉴权 HTTP 分页，历史超过 100 条仍可查看。WS 快照会裁剪近期聊天/回答，给 `welcome` 的游戏视图预留空间，避免超出 16 KB。

完整运行的第五项曾在人工延迟队列尚未发送“回大厅”动作时立即刷新页面，导致测试仍停在结算页。测试现已先等待服务器确认进入大厅再导航；产品代码未因此修改，第五项单独复验通过。历史失败日志保留，避免把复验结果冒充一次全绿运行。

E2E 的五个场景：

1. 建房 → 加入 → 提议/同意 → 双方准备 → 翻牌 → 收藏 → 回答 → 并发下一张 → 10 张结算 → 保存图片 → 再来一局；包含跨换卡和结算后保存草稿的回归检查。
2. `?lag=300&jitter=40` 双向延迟：完整一局、双方确认再来一局、刷新恢复同一卡片、纯文本聊天、第三人满员、重复标签页接管。
3. 浏览器 `context.setOffline(true)`，服务器发现掉线后继续等待 30 秒，再恢复网络，两边继续同一张卡。
4. 1440px 桌面和 360×640 手机尺寸：首页、分类、未开放游戏介绍、弹层 Escape 关闭、房间码整串粘贴与规范化、无横向溢出。
5. `?lag=200&jitter=40`、360×640 实际游戏操作区不被底栏遮挡、复制 API 和传统复制均失败时展示可选中链接，以及原页面 `?lag=600` 时接管后保持停止重连。

单元/集成另覆盖：当前/未来卡视图裁剪、错误回合、`STALE`、aid 重放、并发入座、60 秒中断、切后台仅更新回合类 presence、设置权限与准备失效、过期删除、凭证摘要、一次性换设备、新旧连接关闭顺序、服务器重启后的 SQLite 恢复、版本与鉴权错误、创建限流、16 KB 入站帧限制、大历史快照限长、问答本分页以及延迟队列保序。

## 设计取舍与边界

- 按 §12 的 M0 范围实现；邀请二维码图、其他九款游戏、画廊、小约定、commit-reveal、物理回滚和战绩统计界面仍属于后续里程碑。
- 房间码采用一个整串输入框，支持过滤易混字符、转大写和整串粘贴；未拆成六个独立输入格。
- SQLite 使用文档指定的 `DatabaseSync`，短写入在状态变更后同步完成；未额外引入后台线程。表结构采用房间元数据 JSON、独立问答与结果表，后续字段可按需迁移。
- 问答本先交付聊天卡回答和收藏所需能力；M1 的问答游戏扩展未实现。聊天只保留运行中房间的近期消息，重启不恢复聊天；回答和收藏持久保存。
- 新增鉴权 HTTP 接口 `/rooms/:code/rebind-link`、`/rooms/:code/favorites`、`/rooms/:code/journal?offset=N`，分别支持换设备链接、收藏和回答分页。
- 解散按 §5.4 的“任一方可以操作、二次确认”实现；设计 §6.2/通用 consent 中“双方同意解散”的不同表述暂不采用。没有执行任何实际用户房间的解散。
- 对局只存在内存，服务器重启后回大厅并提示，符合 §5.4；收藏、回答和已聊卡片不丢。卡组全部聊过后会结束，可选择未聊过的其他卡组。
- 不禁用页面双指缩放，以保留阅读无障碍；M0 没有需要拦截双指手势的游戏画布。

## 尚未验证

- 没有真实 iPhone、Android 手机、微信内置浏览器或 Wi-Fi/4G 双网络手测；这里的“双人手机”证据是两个独立 Chromium 浏览器上下文和手机尺寸模拟，不能等同真机验收。
- 未做百房间压力测试，也未验证美国服务器到国内用户的真实延迟；记录的是本机人为延迟注入。
- 部署只在现有 HTTPS 虚拟主机增加 `/duo/` include，并新增专用 nginx 配置、独立服务用户与 systemd 服务。现有业务源码、DNS、证书及认证配置未改；没有执行磁盘清理。原有商店、网络面板、工作台入口响应已复查。
- 现有 443 的 SNI 转发会隐藏访客 IP，建房和 nginx 的 IP 限流在该入口合并计算；具体额度与限制见 `DEPLOYMENT.md`。自动浏览器验收从 VPS 访问公开域名，仍不代替国内真机与运营商网络测试。
